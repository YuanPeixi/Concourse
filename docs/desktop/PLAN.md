# Concourse Windows 桌面版实施计划

计划日期：2026-11-10。此文件定义目标与验收，不表示已经实现。
执行状态统一记录在 PROGRESS.md；交接提示词见 START.md。

勾选表示对应实现单元已落盘且有本机自动化/构建证据，不等于该阶段发布验收通过。真实账号、干净机器与系统交互验收单独见 PROGRESS.md / TEST-REPORT.md。

## 目标与范围
面向少量用户，支持 Windows 10/11 x64，无需 Python、Node 或开发环境。
采用 Electron + 现有 Vue + Python；Python 保留抓取、数据库、调度与提醒计算，Electron 负责窗口、托盘、自启动、系统通知与子进程管理。
保留已有功能和界面风格；不新增 AI 入口、手动编辑、多账号、云端、外部插件、版本检查或自动下载。
四个平台为学者网、Moodle、iTest、Codeforces。新增平台随客户端整体发版。
每个需要账号的平台，每个 Windows 用户保存一组凭据；Codeforces 公共赛事不要求账号。

## 固定约定
- 客户端、后端、适配器统一发行版本；数据库 schema 和配置各有独立版本。
- 正式数据根目录为 %LOCALAPPDATA%\Concourse：数据库、配置、凭据、浏览器状态、日志和备份统一管理。
- 提供显式数据目录覆盖，开发和测试隔离，不能读写用户真实数据来完成测试。
- 新安装平台全部停用，保存配置不自动启用；旧数据导入保留原有效启用状态。
- 首次引导解释并允许调整默认开机静默启动、关闭窗口进托盘的行为；完成引导后启用所选设置。
- 所有业务 API、通知通信统一鉴权；每次启动生成令牌，绑定回环地址的动态端口。令牌不放 URL、日志、命令行参数或前端持久化存储。
- 明确就绪握手、启动超时、健康检查和后端版本校验；不能先探测空闲端口再关闭占用后启动。
- preload 仅暴露必要操作并验证参数；上下文隔离、渲染器沙箱、关闭 Node 集成；限制导航、新窗口和外部链接协议。
- 后台任务在窗口关闭后继续，完全退出、关机与休眠期间不运行。
- 日志、API 错误、数据库 last_error 和诊断导出统一脱敏；密码和 Moodle 私有 URL 按敏感凭据处理。
- 发布使用文件白名单，禁止携带 .env、个人 config.yaml、数据库、浏览器状态、凭据及日志。

- [x] 停止调度、取消/等待抓取、关闭浏览器、结束后端；验证 Job Object 等方案对进程树的约束。
- [x] PyInstaller 目录模式，显式收集适配器和资源；锁定 Playwright 及随包 Chromium，辅助登录使用同一运行时。

边界：没有干净测试机或账号时，标明尚未验收，不能以开发机测试替代。当前 Playwright 官方支持列表为 Win11+，Win10 目标需要独立兼容验证或受支持的运行时选择，未解决前不宣称支持 Win10。

## M4：提醒、自启动与唤醒
- [x] 标准化提醒目标：作业截止、比赛开始；考试明确采用开始/截止规则；全天事项明确本地时刻，无目标不提醒。
- [x] 已知完成/提交、删除事项不提醒；Moodle 等未知提交状态不可伪称已知，支持已有本地完成标记。
- [x] 本地完成状态不被抓取覆盖；平台停用停止后续提醒但保留事项。
- [x] 默认提前 24h/1h，可修改统一提前量或关闭；存储使用统一时间语义并覆盖时区与时钟变化。
- [x] Python 持久化待通知记录；按事项、目标时间、提前量去重；Electron 主进程投递并反馈。
- [x] 投递前重查状态；目标时间和设置变化取消失效记录并重算。
- [x] “已发送”只代表交给系统接口；发送后确认前崩溃允许偶发重复，不宣称严格一次投递。
- [x] 启动/唤醒有限并发补抓取，各平台完成或超时后重算，不被单个平台阻塞。
- [x] 默认汇总最近 24h 漏提醒，同事项合并；首次启用或导入建立基线，不推送大量历史提醒。
- [x] 通知点击打开事项，已删除给出提示；自启动静默，托盘设置与退出可用。
验收：可控时钟覆盖去重、目标变更、完成/删除、设置变化、重启、发送失败、补提醒和唤醒。

## 实施与验证原则
按 M0 → M1 → M2 → M3 → M4 → M5 推进，阶段依赖满足后继续。M1 仅做安装所需的最小改造，复杂配置和提醒按后续阶段实现。
验证投入重点放在迁移、认证、进程生命周期、凭据边界、平台互斥与提醒；可逆的小改动不为凑覆盖率添加实现镜像测试。
实现前核对所选版本的官方文档、系统支持和打包限制，记录实际选型，不凭旧知识宣称兼容。

# 数据库升级与恢复

桌面数据库通过 SQLite `user_version` 标识版本。版本 0 仅接受本仓库旧 events/staged_events/fetcher_states 结构，允许旧库缺 course/deleted_at 或尚未创建 fetcher_states；未知表、缺少其他列及更高版本均拒绝启动。空库依次初始化到版本 2；版本 2 增加提醒设置和投递记录。版本 1 升级前同样备份。

升级前，在写锁内使用 SQLite backup API 复制一致的已提交快照到数据根目录 `backups/schema-0-*.sqlite3`，并执行完整性检查。迁移 DDL 与版本号处于同一显式事务，失败回滚且停止启动。不会对同一已升级库重复备份。

恢复时先完全退出 Concourse，确认后台进程已结束。保留失败数据库及其 -wal/-shm 文件作为故障副本，勿覆盖唯一副本。在离线状态复制对应升级前备份为数据目录的 concourse.db，移开旧 -wal/-shm，然后启动匹配该 schema 的版本。备份可能包含个人日程，不应随诊断或安装包分发。

当前只测试本项目已知旧结构、升级失败回滚和拒绝未来版本；不自动修复任意损坏文件，不合并已有数据库。首次导入在临时副本中完成迁移；普通失败回滚。每次文件发布前写入并同步 import-journal.json，启动会检查校验值并回滚未提交副本；若文件被更改则拒绝覆盖，保留源数据和故障目录。模拟中断回滚及重新导入已通过测试，真实断电/磁盘故障仍未验收。
